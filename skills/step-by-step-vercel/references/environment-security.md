# 环境与安全

本参考仅涵盖环境变量、密钥、访问保护与敏感信息遮盖的详细单步教学规则；不提供部署、DNS 或排错流程。

Last verified: 2026-08-03

官方依据：[Environment Variables](https://vercel.com/docs/environment-variables)、[Managing environment variables across environments](https://vercel.com/docs/environment-variables/manage-across-environments)、[vercel env CLI](https://vercel.com/docs/cli/env)、[Vite on Vercel](https://vercel.com/docs/frameworks/frontend/vite)。

## 开始前：只识别，不改值

在创建、更新、删除或调整范围前，本轮只确认项目、变量名称（不得包含值）、变量用途、目标环境、目标 Git 分支（如适用）以及该值是否已经可能泄露。信息不足时，只要求用户提供经遮盖的 Settings 页面或回答其中一项；不得猜测范围。

不得要求用户发送真实密钥、Token、Cookie、完整 Value、`.env` 文件内容、命令输出中的值，或包含这些内容的未遮盖截图。真实值只能由用户在 Vercel Dashboard 的安全输入框或交互式提示中亲自输入；教学回复、命令示例和证据中均不回显值。截图必须遮盖 Value、二维码、Token、Cookie、私有 URL 参数及任何可据此复原密钥的信息；只保留变量名称、环境标签和状态。

## 范围决策：每次只选择一个分支

先按实际用途选择且仅选择下列一个动作分支，不能把多个环境或范围合并为一步：

1. 若只供本机开发使用，选择 **Development**；它用于本地开发（包括 `vercel dev` 或开发命令），不得据此假定 Preview 或 Production 已有同名值。
2. 若供非生产分支的预览使用，选择 **Preview**；默认 Preview 变量可应用于所有非 Production 分支的下一次 Preview 部署。
3. 若仅供线上用户面向的发布使用，选择 **Production**；此范围的任何新建、更新、删除或范围调整均为高风险，必须先完成独立风险确认。
4. 若只有一个指定的非生产 Git 分支需要不同值，选择该 **Preview** 分支专用变量；它会覆盖同名的通用 Preview 变量。不得把 Production 分支当作分支专用变量目标。

需要对多个环境设置同名变量时，逐环境重复“识别—风险确认（若适用）—单一变更”循环；不得在一轮中同时改多个范围。创建、更新、删除、覆盖或扩大范围都可能改变下一次构建或运行时的行为；删除、覆盖、Production 变更及从较窄范围扩大到更广范围，均需独立风险确认。更安全的替代方案是先在 Development 或 Preview 使用不含生产数据的值验证。

## 客户端公开值与服务端密钥

变量名带有 `NEXT_PUBLIC_` 前缀（Next.js）或 `VITE_` 前缀（Vite）的值可能被打包进客户端可见代码；只能放置本来就允许公开的配置，例如公开 API 地址或公开标识。不得把密码、私钥、访问令牌、数据库连接串或任何服务端密钥使用这些前缀。

若值只应由服务端构建、函数或后端逻辑读取，使用不带客户端公开前缀的变量名，并确认代码没有把它传给浏览器。无法判断框架或读取位置时，只做代码或变量名的只读确认，不引导录入值。

## Sensitive Environment Variables 与值录入

当当前项目页面或计划显示支持 **Sensitive Environment Variables** 时，API 密钥、Token、私钥及其他不可公开值应选择为 Sensitive。该类型旨在使值创建后不能在 Dashboard 再读取；它不改变运行时可用性。若当前界面未显示该能力、用户无权限或不确定，标记为“待确认”，不假定套餐或权限，也不降低“不回显”的要求。

需要录入值时，只引导用户打开相应项目的 Dashboard 环境变量编辑页、选择已确认的单一范围，并在安全输入框亲自粘贴或键入值。不得要求其把值复制到聊天、终端命令行、屏幕共享或截图。更新 Sensitive 值时，将其视为替换而非读取；不要尝试导出、显示或验证旧值。

## 变更生效、下载与验证边界

Vercel 的环境变量变更不会应用到既有部署，只会应用于新的部署。因此，完成一次允许的变量变更后，下一轮只能在取得必要风险确认后请求重新部署；不得声称既有 Production 部署已经获得新值。

将 Production 变量下载到本地会把敏感值写入磁盘，带来终端回显、备份、同步、误提交和他人读取风险。默认不下载 Production 值；更安全的替代方案是使用经遮盖的 Dashboard 配置核对，或在确有本地执行需求且已获独立确认时使用不会将值写入文件的 `vercel env run`。任何本地文件不得贴入聊天，且必须确认其不被提交、同步或共享。

验证时只检查变量名称、目标环境或分支、敏感状态（如适用）以及新的部署是否完成；不读取、不打印、不回显值。若需要证明应用行为，索取不含秘密的结果或已遮盖截图。

## 疑似泄露：固定顺序

一旦怀疑密钥出现在聊天、截图、日志、代码库、终端历史或其他非预期位置，停止继续传播该值。每轮只引导一个动作，并严格按以下顺序推进：

1. 先在密钥提供方撤销或轮换该凭据；不能只在 Vercel 删除变量。
2. 再在 Vercel 将新值更新到已确认的单一环境或分支范围，且不回显新旧值。
3. 取得必要风险确认后，重新部署，使新值用于新的部署。
4. 审计可能的暴露位置与访问范围（聊天、截图、日志、代码库、终端历史、下载文件等），只记录不含值的事实。
5. 通过提供方的安全状态或受限测试确认旧密钥已失效；不得用旧值回显来验证。

轮换前不能假定泄露影响范围，也不能因 Vercel 显示已更新而推断提供方旧密钥已失效。
