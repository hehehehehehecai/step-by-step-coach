# 证据驱动排错

本参考用于 Vercel 的 Git 集成、构建、运行时、环境变量、Functions、域名、网络、权限与套餐排错。它只诊断当前可观察状态；不修改业务代码、不替用户执行生产变更，也不把猜测当作结论。

Last verified: 2026-08-03

官方依据：[Git 集成](https://vercel.com/docs/git)、[构建配置](https://vercel.com/docs/builds/configure-a-build)、[部署概览](https://vercel.com/docs/deployments)、[环境变量](https://vercel.com/docs/environment-variables)、[Functions](https://vercel.com/docs/functions)、[Functions 日志](https://vercel.com/docs/functions/logs)、[域名排错](https://vercel.com/docs/domains/troubleshooting)、[团队](https://vercel.com/docs/accounts/team)、[Hobby 套餐](https://vercel.com/docs/plans/hobby)。

## 总规则：先证据，后分支

每轮一次只检查一个层级：先确认部署状态，再确认构建，再确认运行时或网络；不得同时要求多页截图、多个命令或多个配置变更。证据不足时，只索取一个经过遮挡的 Dashboard 截图（保留项目、环境、状态和错误摘要）或一段**完整报错**；必须遮盖密钥、Token、Cookie、连接串、环境变量 Value 和私有 URL 参数。

每个分支都按“可观察证据 → 唯一最小只读检查 → 停止条件”推进。Dashboard 是默认检查渠道。只有用户明确选择 CLI、该命令能读取当前单一证据且官方文档支持时，才在本轮给出一个命令；不得输出命令清单或把命令串联。

若当前错误无法归入下列单一分支，停止诊断并仅收集上述一项证据；不得通过修改设置来试错。

## 先定位：部署与环境是否一致

| 可观察证据 | 唯一最小只读检查 | 停止条件 |
| --- | --- | --- |
| 页面问题只出现在一个 URL，或用户只说“线上不对” | 在该 URL 对应部署详情读取 **Preview** 或 **Production** 环境标签 | 看不到部署、环境或 URL 对应关系时，停止并索取该部署详情的遮挡截图 |
| Preview 正常、Production 异常，或相反 | 只读取异常侧部署的状态与提交/分支标识，不比较第二个部署 | 环境标签与用户所述不一致时，停止；先纠正排查目标，不推断配置差异 |
| 部署不是 Ready | 只读取该部署的当前状态（Queued、Building、Error 等） | 状态仍在变化时，停止并等待状态稳定；不是 Ready 时不要跳到运行时、域名或网络分支 |
| Ready 但目标 URL 无法达成预期 | 只确认该部署的目标 URL 和环境标签 | URL、项目或环境无法确认时停止；不要把 Ready 当成域名、Functions 或外部服务正常的证据 |

## Git 集成与导入权限

| 可观察证据 | 唯一最小只读检查 | 停止条件 |
| --- | --- | --- |
| 导入页没有仓库，或显示 Git 集成/授权失败 | 只读取导入页中 Git 提供方的可见授权或错误状态 | 没有明确错误、仓库归属或当前登录身份时，停止并索取遮挡截图或完整报错 |
| 仓库可见但导入失败 | 只读取该次导入失败的错误摘要 | 错误指向权限、仓库不存在或安装范围不明确时，停止；不得重装集成、改变仓库权限或重新导入来试错 |
| 推送后未产生预期部署 | 只读取项目 Git 设置中的已连接仓库与生产分支 | 连接仓库、分支或提交无法确认时停止；不得据此推断 Webhook、提交权限或构建已经失败 |

涉及仓库、Git 提供方或 Team 权限的改变属于权限变更，必须先满足核心 Skill 的风险确认契约；本参考只收集证据。

## 依赖安装、构建与输出

| 可观察证据 | 唯一最小只读检查 | 停止条件 |
| --- | --- | --- |
| Deployment 为 Error，日志出现 install、package manager 或依赖解析错误 | 只读取失败部署日志中的第一个明确错误块 | 没有完整报错、日志疑似含秘密，或错误块不能确认时停止；不得建议更换包管理器或锁文件 |
| 日志显示 build command 失败 | 只读取失败部署的 Build Logs 中首个非零退出错误 | 首个错误无法定位、或日志只显示后续连带错误时停止并索取完整报错；不得同时改 Build Command、框架和依赖 |
| 构建完成却提示找不到输出目录/产物 | 只读取项目 Settings 当前显示的 Output Directory | 当前值或框架检测结果不可见时停止；不得用猜测路径覆盖设置 |
| 单体仓库或子目录项目构建找不到文件 | 只读取项目 Settings 当前显示的 Root Directory | 仓库结构与当前 Root Directory 无法从证据确认时停止；改变 Root Directory 是高风险动作，不能在排错轮执行 |

这些证据仅说明某次构建在对应步骤失败，不能推断所有分支、所有部署或代码本身均有同一问题。

## 环境变量范围与旧部署

| 可观察证据 | 唯一最小只读检查 | 停止条件 |
| --- | --- | --- |
| Preview 与 Production 行为不同，且用户怀疑变量 | 只读取异常环境的变量名称与适用范围，不读取 Value | 变量名、环境或分支范围不清楚时停止；不得索取或回显值 |
| 变量刚变更但原 URL 行为未变化 | 只读取变量变更后的最近一次部署创建时间与环境 | 没有新的对应环境部署时停止：环境变量不会回填旧部署，不能宣称变更已生效 |
| Functions 或构建提示变量缺失 | 只读取报错中的变量名称（如可安全显示）及该部署环境标签 | 名称本身敏感、报错含值，或范围不可确认时停止并要求遮挡证据；不要创建占位变量来测试 |

变量创建、更新、删除、扩大范围和 Production 重新部署均不在本参考执行；分别遵循[环境与安全](environment-security.md)的遮挡、范围与风险确认规则。

## Functions 运行时与日志

| 可观察证据 | 唯一最小只读检查 | 停止条件 |
| --- | --- | --- |
| 部署 Ready，但请求返回 5xx、超时或 Functions 错误页 | 只读取该请求时间附近的一条 Functions 日志错误事件 | 没有请求时间、部署环境或安全日志摘要时停止；不得将一次错误归因于代码、变量或第三方服务 |
| Functions 日志显示运行时异常 | 只读取异常类型和首个堆栈位置，遮盖请求头、Cookie 和任何值 | 日志含秘密或无法关联到目标部署时停止并索取遮挡截图；不在本参考修改函数代码 |
| Functions 未被预期调用 | 只读取该部署的 Functions 视图中对应函数是否存在及状态 | 函数名称、路由或部署无法关联时停止；不要根据不存在的日志断言函数一定未部署 |

日志是单次请求的运行证据，不等价于数据库、外部 API、身份服务或所有用户请求健康。

## 域名与网络连接

| 可观察证据 | 唯一最小只读检查 | 停止条件 |
| --- | --- | --- |
| Vercel Domains 显示 Invalid Configuration、验证待完成或 SSL pending | 只读取 Domains 页面针对该域名的当前诊断 | 当前诊断、域名或所属项目不明确时停止；不得硬编码 DNS 目标或删除记录 |
| 部署 URL 可访问而自定义域名失败 | 只读取该自定义域名在 Domains 页面中的状态 | 状态不是 Active 或诊断不充分时停止，并转入[域名与 DNS](domains-and-dns.md)；不要把部署 Ready 说成域名已连通 |
| 域名 Active 但访问仍失败、超时或连接被拒绝 | 只读取一次不含凭据的浏览器错误页面/网络错误摘要 | 错误未说明 URL、时间或响应类型时停止；不得同时排查 DNS、Functions、访问保护和外部网络 |
| 只有受保护路径或登录后的请求失败 | 只读取错误状态码或访问保护页面名称 | 缺少状态码/页面证据时停止；不得要求 Cookie、Authorization 头或真实账号会话 |

任何 DNS、域名绑定、证书或访问保护的修改都不是排错中的默认动作，且可能影响线上服务或邮件；先依照对应参考完成盘点与风险确认。

## Team、项目权限与套餐限制

| 可观察证据 | 唯一最小只读检查 | 停止条件 |
| --- | --- | --- |
| Dashboard 显示无项目访问、禁止操作或成员权限错误 | 只读取当前 Team/项目页面显示的角色或权限错误文字 | 看不到实际错误或当前 Team 时停止；不得猜测用户应拥有的角色，也不得要求调整成员权限 |
| 操作入口缺失或页面提示需升级 | 只读取当前套餐名称和该功能的页面提示 | 没有套餐名或可见提示时停止；不得把界面缺失直接当作产品故障 |
| 用户把限制、配额或可用性问题称为“Vercel 坏了” | 只读取 Dashboard 对该操作显示的具体限制/配额提示 | 提示未明确说明原因时停止；不得猜测剩余额度、重置时间或承诺升级一定可解决 |

对 **Hobby**，只以当前页面提示和官方套餐文档判断可见限制。套餐限制、权限不足与产品运行错误是不同分支；在没有明确证据前，不能互相替代解释。

## 结束与升级

只有单一分支的证据同时满足“目标项目/部署可识别、目标环境可识别、当前错误或状态可复现描述”时，才能给出下一轮的一个最小检查。若证据冲突（例如 Dashboard 与 CLI 或两个部署状态不一致），停止所有修改，保留两份遮挡证据并请用户确认当前项目、环境和时间点。

本参考不能证明业务代码正确、第三方服务可用、网络在所有地区正常或套餐一定足够；这些均应标为待确认，并由相应的单一可观察证据继续排查。
